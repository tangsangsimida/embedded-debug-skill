# CLI reference

`edbg --help`, `edbg --version`, `edbg doctor --json`, `edbg discover --json`, `edbg config validate --json`, `edbg probe list --json`, and `edbg connect` are available. Connect discovers IDE OpenOCD arguments and existing ELF files when unambiguous. It automatically reuses an open local GDB Server, then asks GDB to validate the target connection. A standalone `target.cfg` and `.edbg.toml` are optional; an existing board/full config, IDE launch entry, or OpenOCD command is sufficient. Explicit CLI settings override the optional project TOML. Global tool overrides are `--gdb` and `--openocd`; `--config` selects optional TOML. Connect supports complete configs, interface/target/board, extra OpenOCD commands, loopback host, GDB port, adapter speed, and ELF.

`--json` emits `success`, `command`, `timestamp`, `target`, `target_state`, `data`, `error`, and `diagnostics`. Exit code 0 means command/diagnostic completed; 2 indicates rejected or failed operation; 1 indicates a build failure. A successful `doctor` command may report missing optional tools in its data.

Build discovery supports existing VS Code build tasks, CMake, Make, and PlatformIO. Build and flash commands are executed as argument arrays only after explicit workspace-command authorization; flashing also requires operation authorization. Register/variable/stack/breakpoint/memory commands use one persistent GDB/MI session across CLI processes. `edbg session cancel --authorize-run` interrupts an in-flight GDB/MI operation from another CLI process; this can halt target execution. Memory writes, reset, and running/stepping also require explicit flags. SVD, validated HardFault decoding, RTOS-specific thread decoding, and telemetry remain incomplete.
